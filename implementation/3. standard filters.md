# 3. PipeIgnore Standard Filters Implementation Specification 1.0

## 1. Purpose

`pipeignore-filters` implements PipeIgnore Standard Filters 1.

It is optional from the perspective of Core but included by default by the
high-level `pipeignore` package.

## 2. Exported Filter Collection

The package SHOULD expose the complete standard filter collection as a single
value.

Conceptually:

```text
standardFilters
```

containing:

```text
has
has-all
```

This allows explicit composition:

```text
filters = {
    ...standardFilters,
    ...customFilters
}
```

## 3. Individual Exports

Implementations MAY additionally expose individual filter functions.

For example:

```text
has
hasAll
```

The language-specific identifier need not exactly match the PipeIgnore textual
filter name.

## 4. `has`

API:

```text
has(path, names, context) -> boolean
```

or equivalent.

It implements Standard Filters `has`.

It MUST test immediate child entries only.

It MUST NOT require those entries to be directories.

Names MUST be interpreted literally and MUST NOT be treated as glob or
Git-ignore patterns.

The implementation MUST inspect immediate child entries only.

At least one name is REQUIRED. An invocation with no names MUST produce an
invalid-arguments error.

If the current path exists but is not a directory, `has` MUST return `false`.

A filesystem error preventing inspection of the current path or its children
MUST be reported as an error rather than converted to `false`.

## 5. `has-all`

API:

```text
hasAll(path, names, context) -> boolean
```

or equivalent.

It implements Standard Filters `has-all`.

Names MUST be interpreted literally and MUST NOT be treated as glob or
Git-ignore patterns.

At least one name is REQUIRED. An invocation with no names MUST produce an
invalid-arguments error.

If the current path exists but is not a directory, `has-all` MUST return
`false`.

A filesystem error preventing inspection of the current path or its children
MUST be reported as an error rather than converted to `false`.

## 6. Filesystem Access

Filters SHOULD use a filesystem abstraction supplied through context where
practical.

This allows:

- testing without real filesystem mutation;
- virtual filesystems;
- sandboxed applications;
- alternate storage implementations.

The canonical implementation MAY use the native filesystem by default.

## 7. Standalone Commands

The canonical implementation SHOULD expose Standard Filters as independent
commands.

Recommended command names:

```text
pipeignore-has
pipeignore-has-all
```

Shorter aliases MAY be provided if they do not create undesirable namespace
conflicts.

Whether executable aliases such as plain:

```text
has
```

are distributed SHOULD be decided by each ecosystem's packaging conventions.

## 8. CLI Semantics

Each command operates as a stream predicate:

```text
input paths
    ↓
filter
    ↓
accepted input paths
```

Filter-specific arguments are supplied on the command line. Candidate paths are
supplied through standard input.

For example:

```text
producer | pipeignore-has .git .hg .svn
```

emits paths containing at least one requested child.

The command emits the original path record only when the underlying `has`
predicate returns `true`.

The CLI layer emits paths.

The underlying filter function returns booleans.

## 9. NUL Mode

Standalone filter commands SHOULD support NUL-delimited input and output.

## 10. Exit Status

For stream operation, exit status SHOULD describe processing success, not
whether output was produced.
