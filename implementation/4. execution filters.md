# 4. PipeIgnore Execution Filters Implementation Specification 1.0

## 1. Purpose

`pipeignore-filters-exec` implements PipeIgnore Execution Filters 1.

It MUST NOT be included in the default high-level PipeIgnore filter collection.

Users explicitly opt into execution capability.

## 2. Exports

The package SHOULD expose:

```text
executionFilters
```

containing:

```text
exec
shell
```

Conceptually:

```text
filters = {
    ...standardFilters,
    ...executionFilters
}
```

enables execution filters.

## 3. `exec`

API:

```text
exec(path, args, context) -> boolean
```

or equivalent.

The in-process `exec` filter MUST:

- invoke the specified executable directly;
- preserve argument boundaries;
- avoid shell interpretation;
- substitute defined path placeholders;
- map successful exit status to `true`;
- map ordinary unsuccessful status to `false`;
- distinguish process-launch failure from predicate rejection.

The canonical implementation MUST implement `{}` substitution structurally
within each argument value before invoking the child process.

The canonical implementation MUST distinguish an unescaped `{}` placeholder from
the escaped sequence `\{}` preserved by Core.

An unescaped `{}` MUST be substituted with the current path.

An escaped `\{}` MUST produce the literal characters `{}` and MUST NOT undergo
path substitution.

The current path MUST NOT be implicitly appended when no `{}` placeholder is
present.

Placeholder substitution MUST NOT invoke a shell or alter argument boundaries.

## 4. `shell`

API:

```text
shell(path, args, context) -> boolean
```

or equivalent.

The `shell` filter MUST explicitly invoke a configured shell or
platform-equivalent command interpreter.

The selected interpreter MUST be documented by the implementation.

The API SHOULD permit applications to override or restrict the interpreter.

The canonical implementation MUST treat the first filter argument as `COMMAND`
and any remaining arguments as positional arguments supplied to the selected
command interpreter.

`{}` substitution MUST be applied to positional argument values before
invocation, but MUST NOT be applied inside `COMMAND`.

For POSIX-compatible shells, invocation SHOULD be equivalent to:

```text
sh -c COMMAND pipeignore ARG1 ARG2 ...
```

so that the first supplied argument is available as `$1`.

The canonical implementation MUST NOT require `{}` to occur in a `shell`
invocation.

## 5. Security Defaults

Installing this package MUST NOT automatically enable its filters in existing
PipeIgnore instances.

This:

```text
import executionFilters
```

does not imply registration unless those filters are passed into construction.

## 6. Policy Control

Language-specific implementations SHOULD permit applications to impose:

```text
timeouts
working directory
environment restrictions
process privileges
resource limits
```

where supported.

## 7. Standalone Commands

The package MAY expose standalone utilities, but unlike Standard Filters, this
is not a recommendation.

Their primary purpose is adapting external execution into PipeIgnore's predicate
interface.
