# PipeIgnore Predicate CLI Adapter Implementation Specification 1.0

## 1. Purpose

The Predicate CLI Adapter converts a PipeIgnore-style boolean predicate into a
Unix-compatible path stream filter.

It is reusable by Matcher CLIs, Standard Filter CLIs, and third-party predicate
implementations.

## 2. Predicate Contract

The adapter wraps a predicate conceptually equivalent to:

```text
predicate(path, arguments, context) -> boolean
```

## 3. Input

Predicate-specific arguments are supplied through command-line arguments.

Paths to evaluate are supplied through standard input as records.

## 4. Output

For each input path:

- if the predicate returns `true`, the original record MUST be emitted;
- if the predicate returns `false`, no record MUST be emitted;
- if predicate evaluation fails, the adapter MUST report an error.

## 5. Record Delimiters

The default record delimiter is newline.

The adapter SHOULD provide a NUL-delimited mode selected using `-0`.

The adapter MUST remove only the record delimiter itself.

Path contents MUST NOT be trimmed, normalized, canonicalized, or otherwise
modified before being supplied to the predicate.

Leading and trailing whitespace that is part of a path record MUST therefore be
preserved.

A final record delimiter terminates the preceding record and MUST NOT by itself
create an additional empty record.

An explicitly empty record occurring between two delimiters is a real input
record and MUST be passed to the predicate.

The adapter MUST NOT silently discard empty input records.

In NUL-delimited mode, NUL (`0x00`) is the only record separator.

## 6. Errors

Predicate errors MUST be distinguishable from predicate rejection.

A stream containing no accepted paths is a successful execution and MUST NOT by
itself be treated as an error.
